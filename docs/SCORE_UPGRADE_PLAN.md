## 0. 基线、目标与红线

- 基线：首轮 14/50=28%，E1 后 **15/50=30%**。失败构成：零提交 30、
  已评分失败 5（vul_no_crash 4 + fix_not_clean 2 中经 E1 后余 5 含 42227
  二次同判）。
- **95% 算术**（r7 复审，必须正视）：达到 48/50 需回收 5 个已评分失败中
  ≥4 题 **且** 零提交池回收 28-30/30 = **93.3%-100%**。仅把零提交率从
  60% 降到 20% 远远不够——最终必须几乎解出整个失败池。
- 因此本计划按**双能力框架**组织：
  1. **执行可靠性**：预算内产生、验证、提交候选，不停留在分析阶段
     （X1/X2′/X3′/X4/X5/Y1）；
  2. **漏洞求解能力**：复杂漏洞的可达路径、输入约束满足、bug 特异性
     崩溃（Y2/X6/Y3/X7，以及 Y4 提供的预算基础）。
  v1 过重于 (1)；v2 把 (2) 的杠杆提前并与 (1) 并行。
- 红线（不变，全文见 `FORMAL50_STATUS_AND_PLAN.md` §1 + 
  `SCORE_UPGRADE_PROMPT.md` §4）：不改评分谓词、不泄露 fix 侧、unscored
  不入重试、不绕隔离/25-check 预算门/账本三方一致、无跨题信息、不利用
  评分漏洞。**check 使用率/覆盖率/运行时长本身不是解出率**——它们只是
  中间变量，不得包装成官方口径提升（r7 原文）。
- 实验队列纪律（v2 强化）：A/B/C/D **四臂必须同题**（或预注册的随机
  区组设计），不同队列的原始成功率不得直接相减；12 题规模仅作**机制
  筛选门槛**，不构成固化基线或统计结论的证明；实验跑批与正式跑批分开
  报告；每臂记录 commit SHA 与模板/mission 文件哈希。

### 3.2 X2′ 候选驱动提交门（REJECT 原 X2，重写）

否决理由（r7 接受）："turn 40 保底严格占优"忽略 stab 门存在性（无本地
崩溃候选时保底不可执行）、提交非零成本、以及 final-only 下劣质保底可能
覆盖既有较好提交造成降级。v2 改为**候选状态驱动**，五分支：

| 候选状态 | 动作 |
|---|---|
| 有可信目标相关崩溃（过 stab 门） | 按正常稳定性门提交 |
| 有可解析候选但无崩溃 | 优先本地验证/变异，**不自动提交** |
| 服务器已有接受的提交 | **禁止无新证据的保底覆盖** |
| 完全无候选 | 进入短时构造或换道（X3′），不制造虚假提交任务 |
| 截止逼近且有新证据候选 | 按当题质量判据，在原 check.py 路径完成一次合理验证的提交 |

- 里程碑门保留为**调度信号**而非提交触发器：turn 15 无本地候选→换槽
  决策；turn 30 无→最小 harness + 受监管 fuzz；turn 40 无→收敛写
  `SOLUTION.md`（`STATUS: UNSOLVED` 禁止伪装）+ 若候选状态表命中第 5
  行才提交。
- 纪律继承：stab 门优先于一切提交纪律（r5）；无谓重提交禁令不变。
- 度量（r7 指定）：首提交 turn、总提交率之外，**必须**报告目标相关
  崩溃率、最终通过率、**已有成功任务的降级数**。

### 3.3 X3′ 证据进展换道 + 受监管 fuzz worker（HOLD）

两部分，第二部分实施前阻断：

**（a）换道规则改证据进展分数**：替换 v1"同一槽连续 8 turns"固定阈值，
改为进度信号聚合（新 REACHED/新覆盖/新构造进展/新本地崩溃证据）——
无新证据的 turn 计入停滞，停滞阈值由批次 1 遥测定初值（预注册后才可调）。
8 槽库保留（minimal-reproducer / parser-format / bounds-allocation /
lifetime-state / existing-tests-fuzz / crash-guided-debug /
static-source-sink / alternate-hypothesis）；B2 红线继承：existing-tests-fuzz
只读、含现成目标触发 PoC 的样本排除、启用前人工审计。

**（b）受监管任务内 fuzz worker**（否决 nohup）：后台 fuzz 由**原有隔离
执行环境**负责生命周期，要求全部满足：

- worker 不脱离当前题 UID/cgroup；
- pass1 2400s / pass2 900s 硬窗口不变（后台 fuzz 不延长任何窗口）；
- 输出仅写当前题私有工作区，写回原子化（防 pass2 读到半写文件）；
- 超 wall-time（默认 ≤600s）可回收，保留三态清理语义
  （clean/residual_detected/inspection_incomplete）；
- root 验收能发现 worker 残留（cgroup.procs 检查扩展到 worker 组）。

**上线前置：五路径生命周期验证**——正常完成 / 超时 / 中断 / 主会话
崩溃 / 强制清理，逐项验证无残留、无跨工作区可见性、无预算失控；任何
一项失败即不得进入正式跑批。验证通过前 X3′ 仅上线 (a)。

### 3.4 X4-L1 证据接力最小版（APPROVE WITH CONDITIONS）

**事实修正（r7）**：pass1/pass2 共享同一工作区，代码未删除候选文件；
准确表述是"pass2 **有机会**访问同题现存文件，但没有被可靠地引导去
发现、理解和优先使用 pass1 证据"（`run_agent_task.sh` L576-609 的
PASS2_PROMPT 只点名 description + 至多 5 个 repo 文件）。

**职责拆分（Q2 裁决，取代 v1 的驱动侧 L3 转录摘要）**：

- **root 只读可信元数据**（驱动侧、只读、有限 schema）：
  `poc.bin exists/absent`、`poc_gen.py exists/absent`、
  `local crash evidence: observed/unknown`、`previous check accepted: yes/no`、
  `remaining check budget: N`，渲染进 PASS2_PROMPT 前段：
  "Current-task evidence: … / Next action: inspect available candidate and
  its local evidence first; do not restart source analysis unless the
  candidate is unusable."
- **pass1 agent 任务内 handoff.md**：CLAUDE_MD 纪律要求 pass1 维护
  handoff（当前目标函数、可达性证据、候选状态、已失败假设），pass2
  引导读取。**handoff.md 一律视为不可信数据**——只作辅助线索，绝不
  作为权限、预算、评分或可信证明来源；其中文本不得改变 pass2 信任
  边界（提示注入防护：root 渲染时不执行其中任何指令语义）。
- **L3（转录失败假设摘要）后置**：root 语义解析 agent 转录引入新代码
  面且可能错误归纳/漏报，暂不实施；待 L1+handoff 数据证明增量不足再议。

实验：E6 三臂原设计（A 现状 45+15 / B 60 单段 / C 45+15+L1 接力），
新冻结 20 题；度量加"pass2 首动作是否为检查候选"（行动转化）。

### 3.6 X6 双通道覆盖率反馈 + Y3 目标路径反馈（APPROVE WITH CONDITIONS）

**双通道设计（r7 重定义）**：

| 通道 | 作用 | 可否替代原判定 |
|---|---|---|
| 原 vulnerable sanitizer build | 本地崩溃、签名、目标位置判定 | **是**（本地主证据，不变） |
| coverage-instrumented build | 函数/分支/路径覆盖观察 | **否**（仅辅助反馈） |

- 明确放弃 v1"coverage build 与原 build 行为相同"的验证要求——插桩改变
  布局/优化/时序，**插桩版不崩不证明原版不崩**，两通道结论不互换。
- `try_local.sh` 区分失败类型：仅"正常无崩溃"生成覆盖报告；构建失败/
  超时/运行失败不生成（各自走诊断路径）。
- 懒构建条件（Q4 裁决）：独立构建目录、原 oracle 不动、按需触发
  （首次本地失败后）、wall-time 受限（≤300s，超时回退到无覆盖模式）。

**Y3 目标路径约束反馈（P1，X6 扩展）**：覆盖率最大化 ≠ 目标可达性
最大化。把 reach_graph 候选调用链与 coverage 通道执行结果联合，输出
"目标函数是否进入 / 最近可达节点 / 待验证分支条件"，把反馈从 Top-N
覆盖率升级为**目标距离+阻塞条件**。风险：静态调用图不完整、间接调用
失真——按题标注置信度。验证：与仅 Top-N 反馈对照目标函数进入率、
首次目标崩溃时间、最终成功率。
